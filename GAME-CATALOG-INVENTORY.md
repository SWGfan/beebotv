## How to use this inventory

- Create one website page per row only after a fresh app screenshot has been captured.
- Describe guest play only where the Guests required column says so. Host can start means the catalogue marks the game as not requiring guests; it does not prove a computer-opponent option.
- Every campsite game has a botMove implementation in source. Treat this as implementation evidence only; verify the customer-facing bot selector before publishing a bot-play claim.
- The app bundles an artwork tile for most games. Bundled art is not the same as a website gameplay screenshot.
- Public title recommendations are naming hygiene, not legal conclusions. Use a qualified legal review before commercial launch.

## Required cleanup before public game pages

1. Use **Drop Four** everywhere visible to customers. The Android display title is already correct, but the internal ID is Drop Four and some existing site assets still use that legacy string.
2. Capture a current phone screenshot for every game. Existing site graphics cover only Drop Four, Chess, and Five Dice; they are illustration assets, not a complete game-page screenshot set.
3. Do not publish any references to console emulation or unimplemented games.
4. Add playable website demos only after their rules, bot behavior, guest behavior, accessibility, and mobile controls have been separately tested. A static game page can safely ship first.
